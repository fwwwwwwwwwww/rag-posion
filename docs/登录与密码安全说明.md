## 一、密码是怎么保护的

**核心原则：平台不保存密码，只保存"无法反推"的哈希。**

### 1. 用 bcrypt，不用 MD5/SHA

| 方式 | 是否可用 | 原因 |
|---|---|---|
| MD5 / SHA1 / SHA256 | ❌ | 为"快速计算"设计，GPU 每秒可试数十亿次，离线爆破成本极低 |
| 明文 / 对称加密 | ❌ | 一旦库泄露，密码直接暴露；加密可逆等于没保护 |
| **bcrypt（本项目）** | ✅ | 自适应、可调 cost，计算慢且内存开销大，专门为存密码设计 |

实测哈希串形如 `$2b$12$...`，**长度 60，含算法标识 + cost(12) + 随机盐**。

### 2. 每个用户独立随机盐

bcrypt 自动生成盐并写入哈希串。实测同一密码两次哈希结果不同，
因此**彩虹表无效**，也无法通过比对哈希发现"哪些用户用了同一个密码"。

### 3. 规避 bcrypt 的 72 字节截断

bcrypt 只取前 72 字节，超出部分被静默忽略——这会让"超长密码的不同后缀"
被判为同一密码。因此先做 **SHA-256 预哈希**再交给 bcrypt。

有回归测试覆盖：`A*100 + "x1!"` 与 `A*100 + "y1!"` 校验结果必须不同。

### 4. 密码强度校验（两道）

- **schema 层**：Pydantic `min_length=8` → 422
- **服务层**：`validate_password_strength()` → 400
  - 至少 8 位
  - 至少包含字母/数字/符号中的**两类**（拒绝 `aaaaaaaa`）
  - 拦截常见弱密码（`12345678`、`password` 等）

两层都拦，属于纵深防御；schema 层更早拒绝。

### 5. 密码绝不外泄

- `User.to_safe_dict()` 显式排除 `password_hash`
- 所有响应模型都不含该字段
- 有测试断言：登录与 `/auth/me` 响应中**不含** `password_hash`，也不含任何 `token` 字段

## 二、会话是怎么保护的

登录成功后不再传递密码，而是下发**签名会话令牌**。

### 1. 存放位置：HttpOnly Cookie（关键）

```
Set-Cookie: rag_session=<payload>.<sig>; HttpOnly; Max-Age=43200; Path=/; SameSite=lax
```

| 属性 | 作用 |
|---|---|
| **HttpOnly** | **JavaScript 读不到** → 即使页面被 XSS 注入，也偷不走会话令牌 |
| **SameSite=Lax** | 跨站请求不携带 → 缓解 CSRF |
| **Secure** | 仅在 HTTPS 下发送（由 `SESSION_COOKIE_SECURE` 控制，本地 http 调试时为 false） |
| Max-Age | 12 小时自动过期 |

**对比常见做法**：把 JWT 存 `localStorage` 会被任意 XSS 脚本读走。
本项目前端**不保存任何令牌**，只缓存用户信息用于渲染。

### 2. 令牌本身：HMAC-SHA256 签名

格式：`base64url(payload).base64url(HMAC-SHA256(payload))`

payload 含 `sub`(用户名) / `uid` / `iat`(签发时间) / `exp`(过期) / `jti`(随机串)。

- **签名恒定时间比较**（`hmac.compare_digest`），防时序侧信道
- **过期时间由服务端校验**，篡改 payload 会导致签名不匹配
- **用户被删除/禁用时旧令牌立即失效**（每次校验都查库确认）

有测试覆盖：伪造令牌、篡改签名的令牌都必须被拒绝。

### 3. 密钥管理（这里踩过一个真 bug）

会话密钥来自 `SESSION_SECRET`。若未配置，则**随机生成并持久化到
`data/.session_secret`**。

> **踩坑记录**：最初未配置时每次都随机生成，而签名器被实例化了**两次**
> （`app/auth.py` 中间件一份、`app/api/auth.py` 路由一份），导致
> **A 签发的令牌 B 验不过 → 登录成功后立刻 401**。
>
> 已修复：改为**全局单例** `get_signer()`，并让密钥落盘。
> 后者同时解决了多 worker 部署下的会话随机失效问题。
>
> 排查过程见 git 历史中 `tests/probe_cookie.py`（已清理）；
> 验证脚本 `tests/test_login_flow.py` 保留了这条链路。

该密钥文件**已加入 `.gitignore`**——泄露即可伪造任意用户会话。

## 三、抵御在线攻击

### 1. 暴力破解：失败限流 + 账号锁定

- 连续失败 5 次 → 锁定 15 分钟
- **锁定检查在密码校验之前**，不能靠继续试绕过
- 锁定期间即使密码正确也拒绝

### 2. 账号枚举：措辞与耗时都统一

- "用户不存在"与"密码错误"返回**完全相同的措辞**："用户名或密码不正确"
- 用户不存在时也跑一次**等价的假校验**（`dummy_verify()`），
  避免通过响应时间判断账号是否存在

> 坑：`dummy_verify` 早期实现里现场 `hashpw`，导致耗时翻倍，
> 反而更容易区分。已改为模块加载时预生成假哈希，只做一次 `checkpw`。

### 3. 时序侧信道

签名比较、密码比较、静态 Token 比较都使用恒定时间函数。

## 四、初始管理员账号

首次启动（`users` 表为空）时创建：

- 用户名：`ADMIN_USERNAME`（默认 `admin`）
- 密码：`ADMIN_PASSWORD` 环境变量；**未配置则随机生成并只打印到启动日志一次**

**绝不使用硬编码默认密码**（那等于给所有人留后门）。

```bash
# 推荐做法：显式指定
export ADMIN_PASSWORD='你的强密码'
python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

未指定时启动日志会打印：

```
==============================================================
已创建默认管理员账号（随机密码，仅本次显示）
    用户名: admin
    密码  : xxxxxxxxxxxx
请登录后立即修改密码，或用 ADMIN_PASSWORD 环境变量指定。
==============================================================
```

随机密码**不会**再次显示；忘记只能删除 `users` 表或手动重置。

## 五、验证情况

```bash
python tests/test_auth_api.py     # 38 项：哈希/强度/登录/限流/令牌/改密
python tests/test_login_flow.py   # 19 项：对真实运行服务的完整登录链路
```

覆盖的关键断言：

- 库中不含明文密码、哈希以 `$2` 开头、长度 60
- 同密码两次哈希不同（加盐验证）
- 超长密码后缀不同必须校验失败（72 字节截断防护）
- 弱密码/弱用户名/重复用户名被拒
- 错误密码与不存在用户的措辞一致（防枚举）
- 响应不含 `password_hash`、不含任何 token 字段
- Cookie 带 `HttpOnly` 与 `SameSite`
- 连续失败触发锁定，锁定期间正确密码也拒绝
- 伪造令牌 / 篡改签名令牌被拒
- 登出后会话立即失效

## 六、生产部署检查清单

- [ ] `SESSION_SECRET` 设为足够长的随机串（多机部署必须一致）
      `python -c "import secrets;print(secrets.token_urlsafe(48))"`
- [ ] `ADMIN_PASSWORD` 显式指定，登录后立即改密
- [ ] `SESSION_COOKIE_SECURE=true`（启用 HTTPS 后）
- [ ] `AUTH_TOKEN` 改为长随机串，或留空禁用旧静态令牌
- [ ] 确认 `data/.session_secret`、`.env` 未被提交
- [ ] 生产数据库不要用 SQLite（并发写入受限），按需配置 `DATABASE_URL`

## 七、已知限制（如需更强安全可继续做）

| 项 | 现状 | 加固方向 |
|---|---|---|
| 双因素认证 | 无 | TOTP / 邮件验证码 |
| CSRF | 依赖 SameSite=Lax | 关键写操作加 CSRF token |
| 登录限流维度 | 按账号锁定 | 叠加按 IP 限流、验证码、递增锁定 |
| 密码泄露检测 | 仅本地弱密码表 | 接入 HaveIBeenPwned k-anonymity API |
| 审计 | 记录登录/改密日志 | 独立审计表 + 异常登录告警 |
| HTTPS | 未强制 | 反向代理终止 TLS + HSTS |
